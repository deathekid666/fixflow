# FixFlow audit — 20 September 2026

## Scope and method

Reviewed FixFlow only; Hadaf was not changed. Inventoried 59 pages and 121 API route files containing 184 HTTP handlers. Used a production build, TypeScript, ESLint, dependency auditing, read-only requests to the connected database and public endpoints, browser checks, and isolated regression tests. No real bookings, customer messages, payments, or test accounts were created.

This is a verified repair pass, not a guarantee that every possible workflow is bug-free. Authenticated shop operations still need an end-to-end session with a real test account. Mocked checks are identified below.

## Landing page

Replaced the previous design with a dark navy and blue layout, responsive navigation, an interactive repair-workspace preview, product and workflow sections, honest AI availability text, consistent plan prices, a functional FAQ, and a tracking-reference form. Removed unsupported customer counts and competitor comparisons. Added reduced-motion support, visible keyboard focus, page metadata, and a working `/track` entry point. Preview data is explicitly labelled as sample data.

Checked the menu, FAQ, and preview controls at 320, 390, 768, and 1440 pixels. Confirmed no horizontal page overflow or browser exceptions in the development verification. A final production verification follows the final build.

## Bugs fixed

- **Session validation:** middleware previously decoded JWT data without verifying its signature. It now verifies HS256 signatures, expiry, and required identity data. Protected-page access remains gated; API handlers return JSON rather than redirecting fetch requests to HTML login pages when a cookie is invalid.
- **Loading failure:** failed session requests no longer leave the entire app stuck loading.
- **Cross-shop ratings:** ordinary shop admins can no longer query other shops' ratings. Ratings submitted by work-order ID require a shop-authorized session.
- **Cross-shop attachments:** reads, uploads, and deletion now check the parent work order's shop and exclude deleted orders before touching files.
- **Tracking ambiguity:** tracking and public rating lookups use complete, exact references and exclude deleted orders. Generated tracking links now use the complete reference, including receipt and external API links. Internal operation logs are filtered from public tracking responses.
- **Tracking throttling:** increased the refresh interval from 3 to 15 seconds to avoid exhausting the endpoint's own rate limit; expired limiter entries are pruned.
- **Customer chat:** anonymous access now requires the corresponding complete repair reference. Invalid message types are rejected. Rejected sends preserve the input and show an error. Rejected ratings no longer show success.
- **Post-save notifications:** a notification delivery failure no longer turns a saved booking, customer message, or rating into an apparent failed save.
- **Booking availability:** submissions validate opening hours, closures, slot alignment, duration, and overlap capacity inside a serializable transaction. Conflicts return a retryable response. The saved duration follows the configured slot length.
- **Booking calendar:** invalid calendar dates are rejected, past slots are unavailable, bad slot durations cannot produce an infinite loop, and partial shop schedules agree between public shop information and slot generation.
- **Network recovery:** booking and check-in recover from failed requests instead of leaving controls stuck; directory failures are shown as errors instead of an empty shop list.
- **Directory map:** shop names are inserted as text rather than interpreted HTML. Cancelled asynchronous map setup no longer creates a map after unmount. Reviews now have deterministic recency ordering.
- **Onboarding:** moved the authorization return after hooks to prevent hook-order crashes when the session changes. Replaced the unauthenticated browser-to-provider AI call with an authenticated server endpoint, bounded input, timeout, validated output, and a visible manual-entry fallback.
- **AI error boundaries:** all nine AI endpoints have outer error handling; provider requests have a 30-second timeout and support a configured model override.
- **Trial banner:** the session response now includes the shop's trial end date, and the banner reads that field rather than a nonexistent top-level value.
- **API errors:** every HTTP handler has the shared exception boundary. Malformed JSON returns 400, known missing/conflicting records return 404/409, and unexpected exceptions return JSON 500 without logging full request URLs or query tokens.
- **Tooling and security:** upgraded Next.js from 14.2.0 to 15.5.25, migrated asynchronous route parameters and cookies, updated React and bcrypt, repaired ESLint configuration, and resolved dependency advisories. Build parallelism is bounded for machines with limited memory.

## Incomplete integrations and limits

- **AI:** the local environment has no Anthropic API key. All nine routes return an unavailable response in missing-key regression tests. A credit shortage was **not** observed; live model quality and deployed-account credit status cannot be verified here.
- **Billing:** paid-plan checkout is still a placeholder and no Stripe key is configured locally. The landing page now states that checkout is not available. A real paid subscription cannot be claimed as working.
- **Signed-in workflows:** all pages compile and protected routing was tested, but this audit did not impersonate a user or validate every dashboard action against live shop records. This includes live order creation, inventory adjustments, payments, email/SMS/push delivery, and production TV credentials.
- **Mobile fixture tests:** sample-data checks exercise rendering and error states; they do not prove live booking delivery or production TV-token configuration.
- **Tracking compatibility:** old shortened tracking links must be reissued using the complete reference. Continuing to accept arbitrary prefixes could return another customer's repair.
- **Booking time zones:** the existing system stores booking slot times using its UTC convention. This pass preserves that convention; it does not add per-shop time-zone configuration.
- **Distributed rate limits:** current limits remain process-local. Multiple server replicas do not share a counter.
